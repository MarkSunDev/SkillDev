# Research references and optional AI backdrops

This file covers the four sources that informed this skill and the optional
image-generation workflow. The short version: use references to calibrate
structure, never to copy; use AI for abstract texture only, never for app UI or
the final logo mark.

## 1. iconLibrary

<https://iconlibrary.framer.website> (new domain: <https://iconlibrary.top/>)

A curated directory of icon sets with style tags, license labels, and format
information. Useful for:

- comparing stroke language (rounded vs sharp, 1.5 px vs 2 px, open vs closed)
- finding a UI icon family that matches the brand mark
- checking the license before shipping icons

Representative families: Feather, Lucide, Phosphor, Iconoir, Tabler, Heroicons,
Remix Icon, IconPark, Material Symbols, Griddy, Pixelarticons.

Rules:

- Read the license label for each set; "free" does not always mean "no attribution".
- Do not mix three icon styles in one product. Pick one family and one stroke weight.
- A UI icon is not a logo. Do not lift a glyph, recolor it, and call it a brand mark.

## 2. Lucide

<https://lucide.dev/packages>

Lucide is an open-source icon toolkit released under the **ISC License**. It
provides framework packages (`lucide`, `lucide-react`, `lucide-react-native`,
`lucide-vue`, `lucide-svelte`, `lucide-angular`, `lucide-static`, and community
ports) and a consistent 24 × 24, 2 px stroke, round-cap visual language.

Use it for:

- UI iconography that matches a geometric, line-based mark
- a construction reference for stroke weight, caps, and corner radius
- prototyping a product's icon system before commissioning custom icons

Do not use a Lucide glyph unchanged as the brand logo. It is generic by design,
and the Lucide brand-logo statement distinguishes the icon library from a brand
identity. If you adapt a Lucide shape, redraw it on the 100 × 100 logo grid with a
different proportion, a unique cut, or a distinct silhouette.

- Lucide license: <https://lucide.dev/license>
- Brand statement: <https://lucide.dev/brand-logo-statement>

## 3. Mobbin

<https://mobbin.com/>

A searchable reference library of real shipped mobile apps, web apps, and
websites. It is useful for studying:

- onboarding, paywalls, empty states, and navigation patterns
- how real products compose a screen before it becomes a store screenshot
- copy density and hierarchy in actual shipped apps

Free accounts are limited; paid tiers unlock search, flows, and the full library.
Mobbin does not document store-listing requirements; use it for product/UI
research, not as a specification source.

Rules:

- Treat references as evidence of how products are designed, not proof that a
  pattern improves conversion.
- Keep source links and label what you observed vs what you inferred.
- Never copy a screen, flow, illustration, or copy block. Adapt the pattern to the
  product's own content and brand.
- Store screenshots must use your own build, not a Mobbin capture.

## 4. logo-generator-skill

<https://github.com/op7418/logo-generator-skill> (MIT)

A Claude Code skill for generating geometric SVG logos, six or more variants, an
interactive HTML showcase, and AI-generated presentation images via Gemini/Nano
Banana. It contributes:

- the six-variant workflow and the "one or two core elements" discipline
- the eight design principles: simplicity, negative space, precise proportions,
  asymmetry, restraint, focal point, structural stability, rounded cuts
- a useful catalogue of dot-matrix, line-system, geometric, and node patterns
- twelve showcase background styles (void, frosted, fluid, spotlight, paper,
  mist, clinical, UI container, Swiss flat, etc.)

What this skill changes:

- **Deterministic rendering.** Logos and galleries are rendered as HTML/CSS →
  PNG through a local Chromium browser, not generated by an image model.
- **Store-safe outputs.** iOS/Play icon alpha rules, adaptive safe zones, mask
  tests, Apple/Play canvas sizes, and validators are added.
- **Real screenshots.** AI is restricted to decorative backdrops; the app UI
  inside the device is always a real capture.
- **No API dependency for the core workflow.** AI backdrops are optional.

Keep the MIT notice if you redistribute substantial portions of that project.

| logo-generator-skill | MIT | Reuse methodology/code with attribution |
| Bundled fonts | SIL OFL | Use and redistribute with the license files |
| AI-generated backdrops | Provider terms | Check commercial-use terms; keep a record of model/prompt |

Originality rules:

- Do not imitate a competitor's mark, trade dress, or distinctive color system.
- Do not use a celebrity likeness, a trademarked symbol, or a recognizable
  fictional character in a generated backdrop.
- Do not ask an image model to recreate a known logo or a specific app's UI.
- Keep a short provenance record: model, prompt, date, and output file.

## 6. Optional AI backdrop workflow

### What it is for

- abstract fields behind a logo showcase
- paper/frosted/mist textures for a brand presentation
- a marketing poster background

### What it is not for

- app UI or store screenshots
- device mockups
- the final logo mark or wordmark
- text, labels, or typography inside the generated image

### Configuration

Use environment variables (recommended) or a local config file:

```bash
export IMAGE_API_KEY="..."
export IMAGE_API_BASE="https://api.example.com/v1"
export IMAGE_MODEL="grok-imagine-image-quality"
```

Or pass a Markdown/JSON config:

```bash
python3 scripts/generate_backdrop.py \
  --config "/path/to/ai_config.md" \
  --style ink \
  --out out/backdrop.png
```

The Markdown parser looks for a section containing `绘图`, then reads
`API KEY: ...` and `URL: ...`. It never writes the key to disk or into the
generated image. Do not commit a config file containing a key.

### Models and fallback

The script calls `GET /models` and prefers, in order:

1. the explicitly requested `--model` / `IMAGE_MODEL`
2. the config file's first model ID
3. `gpt-image-2`, `gpt-image-2.5`, `grok-imagine-image-quality`,
   `grok-imagine-image`
4. any other model whose ID contains `image` but not `video`

If a model returns `service unavailable`, it tries the next one. `--list-models`
prints the available IDs.

Observed on the tested endpoint, **2026-10-22**:

- available: `gpt-image-2`, `gpt-image-2.5`, `grok-imagine-image`,
  `grok-imagine-image-quality`, `grok-imagine-video`, `grok-imagine-video-1.5`
- `gpt-image-2` and `gpt-image-2.5` returned `service unavailable`
- `grok-imagine-image-quality` returned a 960 × 960 JPEG for a 1024 × 1024 request

Output size can differ from the requested size. The script saves the returned
size; resize or crop explicitly if a fixed size is required. Availability and
model names change; never hardcode a key or assume a model is permanent.

### Prompt recipe

A good backdrop prompt has five parts:

1. **Purpose** — "abstract editorial backdrop for a calm productivity brand"
2. **Material** — "matte paper", "frosted glass", "fine film grain"
3. **Light** — "soft amber glow from upper right", "single softbox"
4. **Palette** — one field, one accent, no more
5. **Composition** — "generous empty negative space in the lower left"

Always append the negative prompt:

> No text, no letters, no words, no logo, no brand mark, no app UI, no device, no
> phone, no screenshot, no people, no objects, no collage, no mockup.

Built-in styles:

| Style | Field | Best for |
|---|---|---|
| `ink` | deep ink + warm accent glow | premium, calm, focus |
| `paper` | off-white cold-press paper | editorial, humanist |
| `frosted` | titanium gray, cold halo | hardware, premium tools |
| `mist` | ivory with pastel haze | wellness, approachable AI |
| `studio` | dark carbon, single softbox | magazine, professional |
| `flat` | solid color, no texture | Swiss, confident |
| `void` | black with micro-noise | security, infrastructure |

### Composite the real logo

Do not ask the model to draw the logo. Generate the backdrop, then composite the
actual SVG mark and type:

```bash
python3 scripts/generate_backdrop.py --style ink --out out/backdrop.png
python3 scripts/make_showcase.py out/backdrop.png logo.svg \
  --name "Harbor" --tagline "Make room to think." \
  --accent "#D9A441" --out out/showcase.png
```

`make_showcase.py` measures the backdrop's mean luminance, picks a contrasting
ink, and renders a 1600 × 1200 showcase with the real vector mark, palette chips,
and a `Showcase · not a store asset` label. Inspect the result; if the mark or
text is hard to read, adjust `--ink`, `--scrim`, or regenerate a quieter backdrop.

### Fictional cast and style packs

- `scripts/generate_cast.py` generates fictional adult portraits from text only.
  It is for mockups, not for real users or a supplied person's likeness.
- `scripts/style_packs.py` picks one of 20 dating/social art-direction packs.
- Read `mockups-and-cast.md` and `dating-style-packs.md` before using either.

### AI QA checklist

- [ ] No text, letters, logos, UI, devices, or people in the generated image.
- [ ] The backdrop is abstract and does not imitate another brand's trade dress.
- [ ] The real mark is composited deterministically; it is not redrawn by the model.
- [ ] Contrast is checked on the actual image, not the prompt.
- [ ] The output is labeled as a showcase/backdrop, not a store asset.
- [ ] Commercial-use terms are acceptable; model, prompt, and date are recorded.
- [ ] The key is in an environment variable or local config, never in the repo.

## 7. Research workflow

1. Collect 8–12 references across the four sources.
2. Tag each with one pattern: `silhouette`, `grid`, `type`, `color`, `device`, `copy`.
3. Write one line per reference: **borrow** (structure) and **avoid** (surface).
4. Sketch six directions before opening a design tool.
5. Check the six against the reference set for accidental similarity.
6. Design the mark in one color first; add color only after the silhouette works.
7. Capture the real app screens; do not use reference screens.
8. Render, validate, and inspect at thumbnail size.

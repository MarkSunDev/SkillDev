# 03 1.0.0 / 1.1.0 划分

## 1. 划分原则

1. **1.0.0 = 可运行的核心闭环**；不是 demo。
2. **1.1.0 = 增量能力 + 完整 parity**；不是“把 1.0.0 重写一遍”。
3. **核心计费/额度/免费权益/支付**必须在 1.0.0。
4. **UI SDK** 不进生产；只允许基础 SDK + 自绘 UI（除非用户明确同意）。
5. 1.0.0 不做“半成品，1.1.0 重写”的功能；只留 seam/flag。
6. 每个 deferred 项有 owner/风险/依赖/验收。
7. 1.0.0 和 1.1.0 共用同一 IA/壳，不换壳（除非产品明确要求）。

## 2. 推荐表格

```text
| 能力 | 1.0.0 | 1.1.0 | 理由 | 风险 | 依赖 |
|---|---|---|---|---|---|
```

示例（通用）：

| 能力 | 1.0.0 | 1.1.0 | 理由 |
|---|---|---|---|
| 登录/Onboarding | ✅ | 保持 | 入口 |
| 核心业务闭环 | ✅ | 保持 | 没它不可用 |
| 基础 IM | ✅ real | 保持 | 核心 |
| 实时音视频 | ✅ real | 打磨 | 核心 |
| 支付 | ✅ 主通道 | 扩展通道 | 钱 |
| 免费额度/首充 | ✅ | 完整边界 | 钱 |
| 增长/观测 SDK | ❌ | ✅ | 不阻塞核心 |
| UI SDK | ❌ | ❌ | 不可控 |
| 新功能 A | ❌/seam | ✅ | 增量 |
| 新功能 B | ❌/seam | ✅ | 增量 |

## 3. 交互流程

1. 展示表格。
2. 问：需要增删改哪几项？
3. 用户修改后重新展示。
4. 用户回复“确认”。
5. 写入 `docs/port/11-scope-1.0.0.md` / `12-scope-1.1.0.md`。
6. 更新 `state.yaml`。
7. 写 ADR：冻结日期、变更规则。

## 4. 变更规则

- 1.0.0 开工后新增需求：默认进 1.1.0。
- 必须进 1.0.0 的：写 ADR + 评估工期/风险 + 用户确认。
- 已开始的 slice 受影响：暂停，重新评估，不带病继续。

## 5. 反模式

- 1.0.0 先不做额度/支付，1.1.0 再补。
- 1.0.0 先做 UI kit，1.1.0 再换自绘。
- 1.0.0 和 1.1.0 两套 IA。
- 把“接 SDK”当成 1.1.0 的全部，忽略业务补齐。

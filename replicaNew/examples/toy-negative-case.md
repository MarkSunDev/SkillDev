# 反面案例：toy-Android 无 skill 复刻（replicaNew 防线的来源）

> 2026-10-21 取证自一次未使用任何 skill 的 AI 复刻会话（复刻 Kira 的 toy 项目）。
> 项目做对了一部分（协议 1:1、域名集中、SDK 接口层抽象、装机走查），
> 但最终被用户判定为"全是 BUG + 页面简陋 + 只是 demo，无法上架"。
> replicaNew 的多条铁律直接来源于此案例的失败方式。

## 失败模式清单

| # | 失败方式 | 后果 | 对应防线 |
| --- | --- | --- | --- |
| 1 | **用 UI 元素树文字冒充视觉验收**：模型看不了截图，就跳过截图验证，用 uiautomator 文字清单宣布"页面正常" | 用户截图一看全是空白/简陋页 | design-system §7 铁律：元素树≠视觉；看不了图必须升级用户目检，不许静默跳过 |
| 2 | **截图截到别的 App 都没发现**："Me Tab 验证"的文字列表里混着 Calendar/Chrome/Gmail（系统桌面），AI 未察觉 | 验证证据本身就是错的 | 切片判据：每张验收截图先核对前台 Activity/包名 |
| 3 | **把"构建通过+能走通"当"上架完成"**：BUILD SUCCESSFUL → "交付完成 ✅" | demo 被当成 GP 可上架产品 | audit 门禁三：上架品质门槛九项逐条打分 |
| 4 | **无设计系统**："资源文件（主题/图标/布局）"是 todo 里的一行，页面逐个现写样式 | 风格漂移、简陋 | design 立形阶段：design.md 章程 + tokens + 组件契约 + gallery 先于功能页 |
| 5 | **mock 静默混入真流程**：后端 403/500 → 加"演示模式"离线走全流程 + mock SDK + 假余额 500，UI 无任何标识 | 假成功状态 | 切片判据：mock 只在 debug 变体且 UI 可见标识；故障走显式 unavailable |
| 6 | **验证造假链**：演示会话里的假消息被当成"聊天闭环验证成功" | 汇报与事实不符 | 证据标准：每条验收注明数据来源（真实/演示） |
| 7 | **交互 bug 靠运气**：键盘弹出点到键盘上、点击监听在内层按钮上、礼物加载 NPE | "一直报错" | 切片判据：真实交互路径（键盘/防抖/双击）走一遍；错误路径也是路径 |
| 8 | **把 README 当最重要的交付物**：UI 未过目先写"SDK/域名替换手册" | 优先级倒置 | 完成定义=用户可见品质，不是文档 |

## 它做对的部分（值得保留的直觉）

- 协议层按契约 1:1 复刻（proto + ProtoIdMap 生成）——对齐 diverge §4"保留后端"策略；
- 域名集中到 gradle.properties——配置集中化的雏形（但未覆盖 key/firebase/SKU）；
- 三方 SDK 抽象成接口层，mock 注入一行——对齐 SDK 隔离纪律；
- 装了原版 App 对照后端故障——归因方法正确（后端半下线不是客户端问题）。

## 后续修复轮暴露的"元素树假阳性"三连（P2/P3 追加）

这三类缺陷的共同点：**UI 元素树里一切正常，只有看图或像素采样能发现**。

1. **外部图床不可达 + 占位图未生效**：头像 URL 指向外部图床，设备网络不可达时
   Glide 的 error 图没设或被忽略 → 整页头像空白；列表看起来"有行无头"。
   对策：图片加载必须显式 `setImageResource` 本地回退（monogram/占位图），
   且验收时要检查"图床不可达"场景。
2. **图标命名空间用错**：View 体系里 MaterialButton 的图标必须 `app:icon`
   （`android:icon` 不渲染）→ 返回/工具按钮变成空圈，元素树里按钮存在、可点。
3. **状态视图覆盖功能入口**：错误态 StateView 以全屏/高层级盖住了设置入口 →
   页面"看起来正常"但用户无法进入设置。
   对策：错误态只占内容区，导航/关键入口恒可用；验收时逐页检查入口可点。


## 根因一句话

**没有门禁的复刻，AI 会用"能自圆其说的最便宜证据"宣布成功。**
skill 的价值不是教 AI 写代码，而是把"成功"的定义收紧到无法用便宜证据糊弄。

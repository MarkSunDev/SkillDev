# 阶段 6：rebind 解绑（主体与账号关联切断）

目标：让新 App 在**基础设施层面**是一个自持的产品——自己的签名、自己的服务、
自己的 SDK 账号、自己的发布主体。产出 `replica/rebind.md`（清单执行记录，逐项打勾）。

buzzme 的教训（见 examples）：一个产品泄露家族身份的地方不是业务代码，而是
keystore 入库、域名族、git 组织、客服邮箱拼法、SDKAppID——这些点每一个都要换。

## 清单

### A. 签名与发布物

- [ ] **新生成 keystore**（不用原项目的任何 jks/keystore 文件、别名、口令；
      buzzme 的口令甚至是明文入库的——绝不复用）
- [ ] 新项目的 keystore **不入库**：口令走环境变量或 CI secret，仓库里只有公钥指纹
- [ ] 上传密钥/签名密钥按新商店账号的流程重新生成；v1/v2/v3 全是新月签
- [ ] Play/App Store 的 App signing 走新账号自己的 key

### B. 包名与商店身份

- [ ] applicationId 全新且非原包名变体（含所有 buildType/flavor 变体）
- [ ] 商店条目：新开发者账号、新名称（过了 diverge 的商标检索）、新图标/截图/描述
- [ ] 不使用 XmlClassGuard 之类的"出包改包"当差异化手段——那是混淆，不是解耦，
      且与"真独立产品"的目标相反；包名从源头就是新的

### C. 服务与域名

- [ ] 新 API 域名族（原 nobuzzme.com 家族 → 新注册的、注册人信息独立的域名）
- [ ] 新 OSS/CDN/媒体桶（若有上传）；**法务三页（隐私/条款/删号）用 `legalH5`
      skill 生成并上传新域名**：site.json 改一处域名，烘焙脚本重跑，全站链接
      与 og:url 同步换新
- [ ] 新客服邮箱模板（不沿用家族的 plus-addressing 拼法）
- [ ] 若保留原后端：在 blueprint 里明示数据面关联，服务端做租户/分区，并让用户
      知情确认这条边界

### D. SDK 账号

- [ ] IM/音视频：新 SDKAppID（腾讯/声网等供应商的"应用"是账号级资源，新应用新 ID，
      账单也走新账号）
- [ ] Firebase：新 project（新 google-services.json，新 sender ID）
- [ ] 推送/统计/归因/崩溃（AppsFlyer、BytePlus、Sentry 等）：新账号新 appKey
- [ ] 支付：Play Billing 绑定新开发者账号；Merchant 账号与收款主体随新主体

### E. 代码仓库与协作痕迹

- [ ] 新代码仓（新 git remote、新组织，或本地起步）；不把原项目文件的历史带过来
- [ ] git 作者信息用新团队的邮箱（或至少不是原项目作者名单）
- [ ] CI 不复用原项目的 runner/镜像/脚本（配置形态本身是指纹）
- [ ] 仓库里不出现原项目名/兄弟项目名（sweep 的 names 列表会抓）

### F. 服务端结算与对账键

- [ ] **app_name 白名单**：服务端若按请求头 `app_name` 做白名单（实战遇到：只有原
      App 的名字返回 200），新 App 必须沿用原值才能通网——这属于服务端契约，不是
      品牌字段。在 blueprint 与 rebind.md 里明示"服务端无法区分新旧客户端"，
      并让用户确认；要彻底独立就让服务端放行新 app_name。
- [ ] 服务端读的 misc/结算键名：保留后端则按服务端契约执行；新后端则整套新键名
- [ ] 设备 ID 前缀、UA、埋点 app_name 等服务端识别字段：全部用新 App 自己的值

## 合规红线（不可谈判）

- 多主体/多账号运营时，**每个主体资料真实**，符合对应商店开发者协议；不做
  "伪装成不同人"的欺诈性陈述。
- 不做审核规避：不检测 reviewer、不做内容 cloaking、不在提审包与线上包之间切换行为。
  （需要合规的内容差异走透明的区域/年龄/账号状态门控，参见 content-policy-gate 的做法。）
- 新产品必须独立成立：自己的隐私政策、条款、客服、账号删除路径、UGC 举报路径。
  每一项都在提交的构建里真实可用，商店审核包描述与实际行为一致。

## rebind.md 格式

每项一条：`项 | 原值 | 新值 | 状态 | 证据（截图/指纹/命令输出）`。
"新值"一栏写哈希/域名等可验证事实；"证据"给出验证命令的输出（如
`keytool -list` 的指纹），audit 阶段会复核。

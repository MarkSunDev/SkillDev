# 阶段 7：audit 验收（三门禁）

复刻完成的定义：**原创性门禁**、**行为门禁**和**上架品质门槛**同时通过。产出
`replica/audit-report.md`。任何一项没过就如实写"未通过 + 原因"，不做粉饰——
报告是给用户做发布决策的，不是过关仪式。

## 门禁一：原创性（simcheck + sweep + 人工复审）

### simcheck 用法与读数

```bash
# 全量口径（含资源文件）
python3 scripts/simcheck.py <原项目> <新项目> --markdown > replica/similarity.md

# 纯代码口径（推荐作为 headline）：排除 proto/生成目录，只比 kt/java
python3 scripts/simcheck.py <原项目> <新项目> --ext kt,java \
    --exclude-glob '*proto*' --exclude-glob '*generated*'
```

- **containment（headline 指标）**：新项目 8-gram 中可溯源到原项目的比例。
  目标 < 5%；> 8% 不通过；> 15% 说明有整块翻译，返工。
  实测参考：toy（Java/MVVM）vs Kira（Kotlin/MVI）全量 4.9%，纯代码口径 1.9%。
- **可疑文件对表**：单个新文件与某个原文件重合 ≥ 20% 就列出。任何一行都值得
  打开人工看：是契约必须相同（生成代码、proto），还是照抄。XML 样板（manifest 头、
  theme、launcher icon）造成的配对通常无害，但要扫一眼确认没有业务文案/布局照搬。
- **高频共享代码块**：多为抄来的工具函数/模板，逐个消灭。
- 已知噪声：语言惯用法（协程/Compose 模板）贡献 1–3% 属正常；阈值已含容忍。
- **排除规则必须显式**：`--exclude-glob` 只用于契约/生成代码目录，且排除的文件数
  会写进报告；**不允许把整个 src 目录都标成"生成代码"**。

### sweep 用法

```bash
python3 scripts/sweep.py <新项目> --config replica/origin.json \
    --allow-glob '*proto*' --allow-glob 'app-config.json' \
    --allow-value "com.pserver"
```

零残留才通过。注意 names 列表必须包含**原项目全家**（kira/buzzme/naya/Lira 这类
兄弟名）——只查一个名字等于没查。sweep 应挂进新项目 CI 的发布流程。

- `--allow-glob` 豁免契约/生成文件（proto 目录、生成代码、集中配置文件）；
  `--allow-value` 豁免服务端契约值（如 proto java 包名）。
- 豁免是"透明"不是"隐藏"：报告会列出豁免文件数与豁免次数，必须写进 audit 报告。
- **原 App 名永远不能豁免**（sweep 会直接拒绝这种参数）——注释里"对齐 Kira/
  移植自 Kira"这类文字是最强的家族指纹，必须清零。
- **豁免集合必须人工抽查**：`*proto*` 这类 glob 会连带豁免 `scripts/proto.gradle`
  等构建脚本，里面的"移植自 X"出处注释 sweep 扫不到——对每个被豁免的文件/目录
  再手工 grep 一遍原项目名与域名，确认豁免只覆盖契约内容本身。
- **验证产物也会被扫**：`.screenshots/` 下的报告、`design.md`、README 里的出处
  表述与旧域名同样命中；规划类文档应放 `replica/`（sweep 默认跳过），其余要清理。
- 实测参考：toy vs Kira 原始 2674 处（2591 处是 proto 包名契约、83 处名字）；
  契约豁免后剩 80 处真实残留（76 条注释 + 4 处域名），全部需要清理。清理到 0 后
  仍要跑一次构建验证"删指纹不伤契约"。

### contrast 复跑

```bash
python3 scripts/contrast.py replica/design/tokens.json
```

design 阶段过了不等于现在还过——切片里若有人往 token 里塞了临时的颜色，
这里会暴露。同时在新项目里 grep 十六进制色值：只允许出现在 Tokens 文件。

### 人工复审（工具抓不到的部分）

- 并排目录树：模块/包/文件组织形状不同（不是镜像）。
- 并排主页面：信息层级与构图不同（同功能 ≠ 同布局；"换色不换布局"直接不过）。
  证据来源：design 阶段的 gallery 截图与 rebuild 切片的真机截图（原 App 截图在
  `replica/screens/` 一一对应）。
- 字符串表：用户可见文案全部重写（法律/事实性文案除外）。
- 资产表：图标/插画/截图无复用。
- 注释抽查：新项目里 grep 兄弟项目名、"对齐/照抄/迁移自"——必须零命中。
- git 考古：作者邮箱、remote、历史无原项目污染。

## 门禁二：行为对等（功能矩阵验收）

### 故障注入与幂等（逐条走一遍，写下预期与实测）

- 断网（请求发出前后各一次）、超时、取消；
- 401/403 会话过期、404 详情缺失、409 重复意图、429 限流、503 后端不可用；
- 畸形响应：错误 content-type、错误信封、超大包体、重定向；
- 旧端点/旧账号的迟到响应——必须被丢弃，不得覆盖当前账号状态；
- 连点提交与快速切 tab；
- 写操作后进程被杀：草稿/待发送必须带原 request identity 恢复；
- 重复购买/礼物/帖子/消息重试：同键复用，不产生第二笔；
- 模糊失败（unknown）的正确处理是保留 pending + 对账路径，**不是盲目重发**。

- `features.csv` 每行 clone 列为 yes / partial(注明缺口) / no(注明原因) / skip(注明理由)。
- **must 行全 yes 才可发布**；按 must=3、should=2、could=1 加权算 parity 分，
  partial 记半分。80+ 且 must 全过 = 达标。
- 抽验收要点（不是看代码，是装机走查）：
  - 核心环全程可走通，数据来自真实服务，无造假状态；
  - spec 里的业务数值逐条核对（配额、计费周期、年龄口径、token 生命周期）；
  - 付费沙箱或测试单真实走通（购买→验单→权益生效→退款路径）；
  - **商店商品 ID 与服务端下发值逐条一致**（金币包/订阅/访客订阅各档），
    对照表随报告提交；
  - 401/切号/断网/弱网行为正确；
  - 埋点事件与 spec 的口径一致（若新接统计）。

## 门禁三：上架品质门槛（GP/ASO 级别，不是 demo 级别）

反面案例的教训：无品质门槛时，"构建通过 + 流程能走"就会被当成"交付完成"，
产出实际是空白页 + 简陋样式的 demo。验收必须以下面这张表打分，任何一条不过
就是"未达到上架标准"，不许用"核心玩法已验证"来抵扣：

- [ ] **每页视觉过目**：全部关键页面截图（真实构建、真机/模拟器），由能看图的
      模型或用户逐张过目；汇报注明哪些页过了视觉验收、哪些只过结构验收
- [ ] **无占位页**：导航里不存在 "coming soon" 式的空 Tab/空入口（要么功能在，
      要么入口撤掉）
- [ ] **系统栏不重叠**：edge-to-edge 下标题/内容与状态栏、导航手势条不重叠
      （按状态栏 inset 高度核对 + 截图目检，不能只看元素树坐标）
- [ ] **首屏大图有加载占位**：卡片/头像加载中显示骨架或底色，不是空白洞
- [ ] **错误文案不泄技术细节**：UI 上不出现请求名/HTTP 状态码/堆栈
      （`GetSubscriptionsV3Request HTTP 500` 这类原文只许进日志，UI 显示人话）
- [ ] **组件契约全覆盖**：页面上每个 dialog/toast/空态/错误态都来自 design 阶段
      的组件 kit，无现场手写样式；grep 十六进制色值只在 Tokens 文件
- [ ] **状态完整**：核心页面的空态/加载/错误不是 Toast 兜底，而是设计过的
      组件状态（contrast.py 已过的配色）
- [ ] **交互真实可用**：键盘弹出时按钮可点、点击目标 ≥44dp、双击不双发、
      返回键行为正确（聊天列表双击退出的家族习惯按 spec 处理）
- [ ] **无静默 mock**：release 构建物理取不到 demo/假数据开关（AppConfig 隔离）；
      后端故障显示显式 unavailable 状态
- [ ] **资损逻辑门控**：免扣费/伪造交易号/体验券绕过/客户端放行购买等路径在 release
      物理不可达（源集隔离 + dex 核验），且服务端对每笔权益二次校验——客户端代码
      里任何"能白拿金币/会员"的分支都是上线阻断项
- [ ] **外部资源有本地回退**：头像/图片在外部图床不可达时显示本地占位（monogram），
      不是空白；图标按钮不是空圈（View 体系检查 `app:icon` 命名空间）
- [ ] **错误态不挡入口**：错误/空态只占内容区，导航与关键入口（设置、返回、
      底部 tab）恒可用
- [ ] **崩溃与错误日志干净**：目标页面路径上无 crash、无持续刷屏的 E 级日志
      （"一直报错"在商店审核里等于拒审素材）
- [ ] **会话存储安全且作用域正确**：按端点+账号隔离，切号后旧数据与迟到响应不可见
- [ ] **媒体有防线**：尺寸/MIME 校验、图片重编码、失败可恢复（不是整页空白）
- [ ] **导航抗压**：请求进行中、快速连点、连续切 tab 下不崩不错乱
- [ ] **lint 与依赖审计通过**：依赖清单里没有 spec 禁止的 SDK
- [ ] **法务三页就位**：privacy/terms/delete-account 由 legalH5 产出并上传新域名，
      客户端 app-config 的链接指向它们，商店后台数据表与页面描述同一套事实
- [ ] **商店素材齐**：图标、五图（真机截图非概念图）、描述/关键词过了
      app-store-prd-metadata 的校验脚本

## 提交包自检（联动其他 skill）

- 商店元数据、五图、审核备注、隐私政策/条款：交给 `app-store-prd-metadata`
  的规范与校验脚本（check_metadata.py / check_gallery.py）。
- 审核备注只描述提交构建里真实存在的功能；演示账号走真实登录路径。
- 隐私政策描述的数据流与实际 SDK 清单一致（rebind 的 D 节是核对来源）。

## audit-report.md 格式

```
# 复刻验收报告
- 日期 / 原项目 commit / 新项目 commit
## 原创性门禁
- sweep: 结果（零残留/残留清单与处置）
- simcheck: containment X%（阈值），可疑文件对处置说明
- 人工复审: 各项 ✅/❌
## 行为门禁
- parity 得分、must 完成度、未完成清单（含原因）
- **parity 数字必须由当前 features.csv 现算**（写明行数与权重口径）；矩阵更新后
  重算，不许沿用旧数（diddo 报告 29/50 与当时 21 行矩阵对不上）
- 抽验收记录（每条附证据：截图/录屏/日志）
## 上架品质门槛
- 清单逐项 ✅/❌；视觉验收覆盖页面数/总页面数
## 解绑复核
- rebind.md 清单状态汇总 + 签名/包名/SDKAppID 的指纹证据
- legalH5 三页 URL + 客户端 app-config 链接一致性
## 结论
- 通过 / 有条件通过（条件列表）/ 不通过（阻断项）
```

## 挂到 CI

三个工具 exit 1 即阻断。建议发布流水线顺序：单测 → simcheck → sweep →
contrast → 构建签名 → 上架物料校验。
